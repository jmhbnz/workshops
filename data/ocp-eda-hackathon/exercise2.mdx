In financial services environments, zero-day vulnerabilities and unexpected runtime process executions require immediate containment to stop lateral movement across cluster networks. SecOps teams cannot afford to wait for an engineer to review an alert at 3:00 AM when an unauthorized execution occurs inside a core transaction processing workload.

In this challenge track, your goal is to wire up Red Hat Advanced Cluster Security runtime policy violations directly into Event-Driven Ansible. When Advanced Cluster Security detects a policy violation such as a rogue shell execution Event Driven Ansible will immediately trigger an Ansible Playbook to isolate the compromised pod via a quarantine `NetworkPolicy`.

> **Background:** [Event Driven Ansible](https://www.ansible.com/use-cases/event-driven-automation) can ingest real-time events from external sources like OpenShift's Prometheus Alertmanager stack. When an alert fires, an ansible rulebook can evaluate the alert payload, and immediately run a remediation playbook.

## 1.2 - Configuring ansible credentials

When event driven ansible receives an event matching certain threat alert criteria we will configure it to automatically run a remediation playbook in response to isolate the workload.

You need to explicitly allow this interaction by creating an API Token with `write` scope for Ansible Automation Platform, and then storing this as a credential within the Event Driven Ansible infrastructure configuration.

## 1.3 - Event driven ansible basics

Create the EDA Project pointing to the threat response rulebooks.

1. Go to **Automation Decisions** > **Projects** > **Create project**.
2. Set **Name** to `secops-remediation-rules`.
3. Set **Source control url** to `https://github.com/jmhbnz/workshops`.
4. Click **Create project**.

Next, create the Decision Environment (DE):

1. Go to **Automation Decisions** > **Decision Environments** > **Create decision environment**.
2. Set **Name** to `SecOps Threat Response Environment`.
3. Set **Image** to `registry.redhat.io/ansible-automation-platform-27/de-supported-rhel9:latest`.
4. Click **Create decision environment**.


## 1.4 - Configuring the rulebook activation

Create a Rulebook Activation that listens for HTTP POST webhooks emitted by Red Hat Advanced Cluster Security on port `5000`.

Go to **Automation Decisions** > **Rulebook Activations** > **Create rulebook activation**.

Enter the following details:
* **Name:** `acs-runtime-threat-listener`
* **Project:** `secops-remediation-rules`
* **Rulebook:** `rulebooks/acs-containment.yaml`
* **Decision Environment:** `SecOps Threat Response Environment`
* **Credential:** `acme-secops-token`

Below is the structure of the `acs-containment.yaml` rulebook evaluating incoming ACS payloads:

```yaml
---
- name: Listen for ACS threat notifications
  hosts: all
  sources:
    - ansible.eda.webhook:
        host: 0.0.0.0
        port: 5000
  rules:
    - name: Match process execution alert on critical banking apps
      condition: event.payload.alert.policy.name == "Unauthorized Process Execution"
      action:
        run_job_template:
          name: acme-secops-isolate-workload
          organization: Default
          post_events: true
```


## 1.5 - Setting up the remediation job template

The EDA rulebook triggers a job template that dynamically applies a zero-trust `NetworkPolicy` to isolate the offending pod and scale down the deployment to prevent further exposure.

1. Navigate to **Automation Execution** > **Templates** > **Create job template**.
2. Fill out the configuration:
   * **Name:** `acme-secops-isolate-workload`
   * **Inventory:** `Demo Inventory`
   * **Project:** `secops-remediation-rules`
   * **Playbook:** `playbooks/secops-quarantine.yaml`
   * **Execution environment:** `Control Plane Execution Environment`
   * **Credentials:** `OpenShift Credential`
   * **Extra variables:** Ensure `Prompt on launch` is checked.

The playbook target logic dynamically parses the payload to generate the following quarantine network policy:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: eda-quarantine-deny-all
  namespace: core-banking-prod
spec:
  podSelector:
    matchLabels:
      app: payment-processor
  policyTypes:
    - Ingress
    - Egress
```


## 1.6 - Wiring Advanced Cluster Security (ACS) to EDA

Now connect RHACS to route violations to the EDA webhook listener service.

1. Log into the **Advanced Cluster Security** console.
2. Platform Administration > **Integrations**.
3. Scroll down to **Generic Webhook** and click **Create Integration**.
4. Set the parameters:
   * **Integration Name:** `EDA SecOps Webhook`
   * **Endpoint:** `http://acs-runtime-threat-listener.aap.svc.cluster.local:5000/endpoint`
5. Click **Test** to confirm connectivity, then click **Save**.

![ACS Integration](/workshops/static/images/ocp-aap/acs-webhook-config.png)

6. Go to **Policy Management** > **System Policies**.
7. Locate or enable the **Unauthorized Process Execution** policy. Under **Policy Notifications**, toggle **EDA SecOps Webhook** to **ON**.


## 1.7 - Challenge: Triggering the threat and validating zero trust

### The Sprint Challenge Tasks:

1. **Trigger the Breach:** Execute an interactive shell or unauthorized binary command inside one of the `payment-processor` pods in the `core-banking-prod` namespace:
   ```bash
   oc exec -n core-banking-prod -it deploy/payment-processor -- /bin/sh -c "nc -l 4444"
   ```
2. **Verify Event Ingestion:** Confirm ACS triggers the runtime alert and posts the JSON alert payload to the EDA Rulebook Activation.
3. **Validate Containment:** 
   * Check AAP job runs to ensure `acme-secops-isolate-workload` executed successfully.
   * Verify the creation of `eda-quarantine-deny-all` NetworkPolicy inside `core-banking-prod`.
   * Confirm the deployment replicas drop or isolation policies prevent any inbound/outbound traffic from the compromised pod.

### Challenge Bonus Points (+15 Mins):
Extend `playbooks/secops-quarantine.yaml` to automatically open a P1 Incident ticket in ServiceNow containing the container ID, pod name, and offending process path before network isolation takes effect.
